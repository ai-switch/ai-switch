# Codex / Claude 直连模式设计

## 已确认需求

- 统一称为「直连模式」。在账号行右侧增加图标按钮。
- 支持 Codex API、Codex 官方订阅、Claude API、Claude 官方订阅四种组合。
- 只修改对应的原生客户端，不停止代理，不改变池成员、暂停状态及其他客户端配置。
- 每个客户端只能直连一个账号；另一个客户端可以独立直连不同账号。
- 首次启用展示说明，推荐算力池精确模式，说明直连是一对一连接及其限制。
- 写入路由配置时仅处理勾选客户端：成功后退出该客户端的直连；未勾选客户端的配置、认证与状态均不得改动。失败不得标记切换成功。

## 代码现状

- `AccountsScreen.tsx` 的 `writeConfigsMutation` 向后端传入本次 clientKeys。
- `route_config_service.rs` 按客户端分别调用配置写入协调器。
- `config_write_service.rs` / `config_writer` 已提供路径锁、写前检查、快照及原子替换能力，应复用而非直接覆盖文件。
- Codex 官方账号导入保留 access_token、refresh_token、id_token、account_id、client_id；配置中保留 last_refresh 等元数据。
- 当前未找到 Claude 官方账号的本机认证写入实现。实施前必须核对受支持客户端版本及各操作系统实际认证存储，不能假设所有平台均只使用 JSON 文件。

## 方案选择

推荐独立的直连配置服务，复用现有安全写入基础设施，不把直连伪装成单账号路由。

替代方案：将账号直接塞入现有路由输入，代码较少，但容易携带路由模型别名及本地地址，且无法安全覆盖官方认证切换，因此不采用。

## 界面

- Codex / Claude 账号行增加「启用直连模式」按钮，写入期间禁用重复操作。
- 当前账号显示「直连中」，提供「恢复算力池」操作，复用客户端选择/写入流程。
- 首次确认说明在本机持久化，取消不写入且不记已确认。
- 文案：推荐优先使用算力池精确模式；特殊兼容需求可使用直连，一次使用一个账号；直连不经过代理，不具备代理重试及故障切换；代理请求日志不覆盖直连流量，本机会话扫描仍可能提供用量；其他客户端保持原状。必要时提示重启客户端。

## 配置与认证

- Codex API：写入客户端支持的上游地址、认证与真实模型名。不能继续使用算力池限定模型别名；不兼容客户端原生协议的账号必须明确拒绝，不能隐式继续走代理。
- Codex 官方：恢复官方 provider 选择，写入正确结构的 auth.json；处理凭据存储配置，避免客户端优先读取旧认证。保留无关配置。
- Claude API：使用原生支持的地址及认证配置，处理会遮蔽 API 认证的 ai-switch 管理项。
- Claude 官方：按实际客户端认证优先级处理 OAuth 凭据及路由环境项，保留无关设置；平台原生安全存储必须通过专用适配器操作。
- 凭据校验、模型选择及协议兼容性检查均在写入前完成。缺少必要字段时不写入，不伪造订阅字段。
- 不擅自修改系统/用户全局环境变量；若它们覆盖客户端配置，明确报告冲突而非宣称成功。
- 原生客户端可能刷新官方 token；必须核对刷新所有权，避免代理与客户端并发刷新同一凭据导致失效。该风险需在官方账号实施测试中验证。

## 安全与一致性

- 前端只提交账号 ID；后端读取密钥，任何返回值、普通日志及诊断包均不含密钥。
- 认证备份按敏感数据保存，复用受限权限策略；不得把认证内容写入可公开读取的配置快照或普通 preview。
- 一次切换涉及的配置和认证为同一恢复单元。先读取校验，按稳定顺序加锁，写入前检测外部修改；中途失败恢复本次已修改项，恢复失败单独报告，绝不覆盖外部新修改。
- 直连状态按客户端记录，不按算力池全局记录；仅成功后更新。通过已管理字段指纹检查外部修改，不将陈旧状态显示为已生效。
- 路由写入成功后，仅清理被勾选且写入成功客户端的直连管理项；其他客户端的配置和认证文件保持字节不变。

## 验收

- 四种账号组合的配置/认证输出与读取路径验证；凭据缺失、协议不兼容、配置损坏均不产生部分写入。
- A 账号切换 B 账号、API 与官方互切、直连与路由互切。
- Codex 与 Claude 同时直连，仅勾选 Claude 写入路由后，Codex 配置和认证字节不变。
- 任一文件写入失败、认证存储拒绝、外部并发修改、状态持久化失败的恢复测试。
- 首次说明确认/取消/再次点击及状态提示测试；响应、日志和诊断脱敏测试。
- 自动化测试只使用临时目录及虚构凭据，不覆盖用户正在使用的真实客户端登录。

## 设计确认与认证依据

用户已确认设计，开始实施。

- OpenAI 官方认证文档：https://developers.openai.com/codex/auth/ ，配置参考：https://developers.openai.com/codex/config-reference/ 。文件认证明确要求 `cli_auth_credentials_store = "file"`；管理员强制的认证策略不能被本功能绕过。
- 本机 Claude Code 2.1.273 的独立临时目录验证：使用虚构 OAuth 数据执行 `auth status --json`，识别为 `loggedIn: true`、`authMethod: claude.ai`、`apiProvider: firstParty`。这验证存储格式，不表示虚构 token 能调用上游；没有读取或覆盖用户真实凭据。
- Claude Code 官方分发的 2.1.50 CLI（https://unpkg.com/@anthropic-ai/claude-code@2.1.50/cli.js ）确认 macOS 的 Keychain service 为 `Claude Code-credentials`，account 来自 `USER` 或 OS 用户名；设置 CLAUDE_CONFIG_DIR 时 service 会追加配置目录 SHA-256 前 8 位。Windows/Linux 使用配置目录下 `.credentials.json` 的 `claudeAiOauth`。
- Claude 在线文档在当前网络返回 HTTP 403，因此未将未打开的文档当成依据。macOS 实际登录切换需要在 macOS 上验证；本机只能验证文件认证及平台适配逻辑。



## 实施补充

- 原生目录共享：使用同一个 Codex / Claude 配置目录的 CLI 和 IDE 插件会一起切换；其他独立客户端目录保持不变。
- 新增直连认证写入是桌面专用命令，远端 Web 不开放该操作；Web 的路由写入仍遵守勾选边界。
- Codex CLI 0.150.1 已在独立临时目录分别识别虚构 API 和 ChatGPT 认证，均返回成功的本地登录状态检查；不涉及上游调用或用户真实登录。
