# 旧 Claude 分组折叠展示设计

## 目标

统一账号池后，旧 Claude 的「默认组 / 未入池 / 已归档」不再与 codex 同名组并列显示，而是自动识别并折叠为一个「Claude 备份分组」入口，底部分组栏不再重复。

## 关键结论

- 可靠识别方式是三个固定系统组 ID：`claude-default`、`claude-out`、`claude-archived`（`migrations/202609080001_route_pool_groups.sql`）；不按显示名、`agent` 或账号 provider 判断，`legacy_group` 标记在 v0.18.1 收敛后已清零。
- 这些组可能被 SaaS 密钥、模型价格、同步、计费历史引用（v0.18.1 因此保留），所以不做数据库合并、不生成可提交的虚拟组 ID；`selectedGroupId`、移动、编辑/删除/激活、导出、拖拽继续使用真实子组 ID。
- 展示采用「单入口 + 真实子组切换」：底栏合并为一个备份分组按钮，点击默认进入原默认组（缺失时回退第一个存在的 child），列表上方用子视图选择器在原默认/原未入池/原归档间切换。数据不混合，分页/筛选/移动契约保持后端单组语义。
- 保持现有能力：子组的激活、编辑、移动、导出不因「备份」标签受限；仅容器项本身没有合计操作。

## 交互规则

- 底栏按原顺序显示真实组；旧 Claude 三组的位置替换为一个「Claude 备份分组」按钮。当前浏览的子组属于备份容器时，容器高亮。
- 点击容器：优先上次浏览的 child，其次原默认组，再否则第一个存在的 child；默认视图（codex 池）不变化。
- 子视图选择器出现在列表上方（筛选区下），列出实际存在的 children 及其真实名称；当前 child 高亮。切换调用现有 `selectRouteGroup(child.id)`，沿用页码/勾选重置。
- 某 child 是当前激活路由组时，容器带「包含当前激活组」提示。
- 批量移动下拉继续列真实组，用 optgroup 标注「Claude 备份」；容器项不可选。
- 无 claude 系统组时不渲染备份入口；软删除组不计入。

## 边界

仅展示层与测试：不改 SQL、converge、分页/导出/移动契约，不重写数据库组名，不混合三个子组的账号列表。保持 main，不提交推送或发布，不修改真实数据库与安装目录，保留既有本地开发改动。
