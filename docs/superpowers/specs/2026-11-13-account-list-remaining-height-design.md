# 账号列表剩余高度修复设计

## 目标

账号页的列表区域占满工具栏、模态接入信息和分组栏之间的剩余高度；空列表、少量账号和长列表都保持分组栏在工作区底部。各模态与隐藏/显示分段栏入口行为一致。

## 已定位问题

`MotionPage` 提供 100% 高度，但 `CodexChannelsScreen` 外壳只有 `space-y-3`，没有有限高度。下游 `AccountsScreen` 的全高 grid 因此随内容缩小，底部分组栏上移。列表原有 `flex-1` 并未丢失；内部 `min-h-full` 叠加也不足以保证空态撑满。

## 推荐方案

接通纵向布局：模态外壳使用全高且可收缩的 flex，分段栏不收缩，账号工作区填充剩余高度。继续使用现有 grid 的四块区域和唯一列表滚动区。内部账号视图/列表内容以 flex 分配可用高度，长内容保留自然高度并在外部滚动区滚动。

不使用 fixed、绝对定位或视口减法：它们会绕开已有 grid 并造成窄窗/模态信息变高时的重叠。此方案已通过实现计划审批。

## 验收与边界

使用真实 AppLayout/MotionPage/CodexChannelsScreen/AccountsScreen 和模拟 API 数据验证 708×650、1024×640 与窄窗口；空态占满、少量列表填充、长列表内部滚动且分组栏不动。检查所有模态及分段栏两种入口。保留所有账号数据、分组、筛选、工具栏和分页行为；不顺带处理重复分组标签，不提交推送或发布。
