# Codex 算力池基线模型配置设计

日期：2026-10-29

## 意图

将算力池当前写死的 Codex 基线模型列表改为可配置列表。Codex 账号页右上角现有的“会话管理”入口改为配置图标，点击后打开基线模型配置弹窗。配置必须真正影响算力池对外模型清单及所有依赖基线模型的路由逻辑，而不是只改变前端显示。

## 目标

- 仅 Codex 页把右上角会话入口替换为“基线模型配置”；其他平台继续保留会话入口。
- 支持在弹窗中查看、添加、删除、调整顺序 Codex 基线模型 ID。
- 配置持久化到 SQLite，使 `/v1/models` 等只有 `SqlitePool` 的代理路径也能读取。
- 未配置或恢复默认时继续使用当前默认列表：`gpt-6-astra`、`gpt-5.6-sol`、`gpt-5.6-terra`、`gpt-5.6-luna`、`gpt-5.5`。
- 后端路由模型清单、配置写入、模型能力/失败范围计算、Agent 启动模型列表和 SaaS 模型目录等消费者使用同一份基线配置。
- 前端模型映射摘要和弹窗展示使用后端返回的当前列表，避免再次维护一份可能漂移的 Codex 列表。

## 非目标

- 不修改 Codex CLI 根级 `model` 的默认选择。
- 不改变账号模型映射、路由池聚合/精确模式或其他平台的默认模型列表。
- 不把任意模型配置扩展为账号级配置；基线模型仍是平台/算力池级设置。

## 方案

采用数据库持久化。新增按平台存储的基线模型配置表和 route-pool 命令/API：缺少记录或保存空列表时由后端返回内置默认值。模型能力模块的基线入口接受调用方提供的覆盖列表；现有默认值保留为后备，确保旧数据和测试仍然安全。

前端新增独立的 Codex 基线模型配置弹窗组件，使用后端返回的 `models` 和 `default_models` 初始化。列表编辑使用明确的上移、下移、删除和新增操作；保存前去除首尾空白、过滤空行并拒绝重复模型 ID。保存成功后刷新算力池、模型列表及相关配置写入状态。

## 约束与一致性

- 数据库存储 JSON 数组，按用户输入顺序保留模型顺序；读取时对非法/空数据回退默认值。
- `/v1/models` 必须在请求处理时读取最新配置，保存后无需重启代理即可生效。
- 配置写入客户端模型清单、模型故障的兄弟模型集合、Agent 启动模型选项和 SaaS 目录都必须传入同一份 Codex 基线覆盖。
- 现有未提交的 `src-tauri/src/services/route_proxy_service.rs` 改动不属于本功能，不能覆盖或回退。

## 验收标准

1. Codex 页右上角显示配置图标；点击可打开配置弹窗，其他平台仍可进入会话管理。
2. 默认安装或恢复默认时 `/v1/models` 中的 Codex 基线模型与当前列表一致。
3. 保存自定义列表后，`/v1/models`、配置写入生成的模型清单以及相关模型状态计算都立即使用新列表。
4. 重启应用后配置仍存在；空列表、重复项、空白项和非法数据库内容不会导致代理不可用。
5. 新增前端交互测试、后端数据库/模型清单测试，并通过项目现有 TypeScript 与 Rust 检查。
