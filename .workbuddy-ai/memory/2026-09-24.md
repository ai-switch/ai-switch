## 修复 ZCode/DSH 非推理模型被写入无效推理档位

- 现象：写入 ZCode ~/.zcode/v2/config.json 后，stepaudio-*/step-image-edit 等非推理模型也带 reasoning 块，ZCode 对其退化成只有 enable/disable。
- 根因：resolve_client_models 对 Codex 平台每个模型都调 codex_reasoning_levels()，该函数在模型不在 profile 表时无条件兜底 DEFAULT=[low,medium,high]，从不返回空 → 连音频/图像模型都被写档位。
- 用户要求：按账号配置的推理等级原样写入，不要自定义额外规则；配了什么写什么。
- 改动（route_model_capability.rs）：抽出 normalize_reasoning_levels(overrides)——只做 trim/lowercase/去重/过滤不认识的档位，**无 profile 兜底**。codex_reasoning_levels 改为调它，空时才回落 profile（Codex CLI 自己的目录仍需要）。
- 改动（route_config_service.rs::resolve_client_models）：Codex 平台改用 normalize_reasoning_levels(model.reasoning_levels)，账号没配就是空 → 第三方客户端(ZCode/DSH)不写推理块。
- 测试：新增 zcode verbatim/omit 测试 + normalize 单测；修 deepseek_harness_write_uses_the_configured_custom_path（原来靠 profile 兜底，现在显式声明 reasoning_levels）。
