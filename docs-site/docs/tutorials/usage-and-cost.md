# 用量、费用与对账

**目标**：能解释统计面板里的每一个数字，把本地估算配准，并知道为什么它不能当账单用。

**你需要**：跑过一些真实请求（至少覆盖两个账号、一个估算价模型）；完成 [跑通第一条请求](./first-request)。

**验收标准**：能指出任意一条请求的价格来源，配出一份自定义价格文件让「无价格」变成有金额，并说出统计面板与本机会话用量为什么不能相加。

## 先建立一条心智模型

每一次转发结束，**成功或失败都记一行**到 `usage_events`：

```text
metric_type = 'request'   amount = 1   unit = 'count'
input_tokens / output_tokens / cache_tokens
price_usd_micros / price_cny_micros / price_currency / price_source
source_label: route_proxy | route_pool_model_test | route_pool
```

价格用**微单位**存整数（1 美元 = 1,000,000 micros），避免浮点累加误差并保留六位小数。USD 与 CNY 各占一列，`price_currency` 记录上游到底报的是哪种。

::: warning 手工点的测试也在统计里
模型连通性测试（`route_pool_model_test`）和真实转发（`route_proxy`）写进同一张表、同一个 `metric_type`，**统计面板不会把它们分开**。频繁点 ✈ 会推高请求数；区分只能看请求列表的「来源」列。
:::

## 第 1 步：读懂四个窗口与六张卡

底部视图切到「统计」，先选时间范围：

| 选项 | 起点 |
| --- | --- |
| 当日 | 本地时间今天 00:00:00 |
| 本周 | 本周一 00:00:00（周日算上周） |
| 本月 | 本月 1 日 00:00:00 |
| 累计 | 不设下界 |

SQL 里只有一句 `AND ue.created_at >= ?`，**只有起点、没有终点**。所以四个选项本质是「某个时刻之后的累计值」，不是分桶统计。

| 指标卡 | 口径 | 最容易误读的地方 |
| --- | --- | --- |
| 请求 | `metric_type = 'request'` 的事件求和 | 含手工测试 |
| 输入 Token | `input_tokens` 求和 | 上游不回 usage 就是 `NULL`，界面显示 `-`，**不做字符数反推** |
| 输出 Token | `output_tokens` 求和 | 同上 |
| 缓存 Token | `cache_tokens` 求和 | 多数上游只给一个合计数，不拆读写 |
| Token 总计 | `input + output` 求和，**再加历史遗留的 `token` 事件** | **不含缓存 token**；带遗留口径所以可能比输入+输出略大 |
| 总费用（USD） | 按币种折算成美元微单位求和 | 人民币按**固定汇率 7.1** 折算，混币种时只是参考值 |

::: tip 金额小于 1 分时会多显示小数
总费用卡片自动增加小数位，避免真实小额被四舍五入成 `$0.00`。请求列表里每行显示的是**原始币种的原始金额**（USD 用 `$`、CNY 用 `¥`，各保留六位小数），那个数字才是精确的。
:::

## 第 2 步：在请求列表里逐条核

指标卡下面是请求列表，按 `created_at DESC, id DESC` 排序，每页 **20** 条，面板打开期间每 **5 秒**刷新。

每行：时间、**账号名**、状态、路径、模型、token 合计、价格、来源、详情。三个字段特别有用：

- **账号名** —— 优先级配对了没有，一眼就知道；故障转移发生时这里会换成备用号
- **模型** —— 请求模型与上游模型不同时显示成 `请求模型->上游模型`，映射生效的证据
- **价格** —— 带「估」表示本地估算；`-` 表示完全没有价格

点「详情」展开，能看到账号 ID、输入/输出/缓存 token、价格、时间，以及两块原文：上游原始响应（成功请求只留前 2 KiB，失败留 16 KiB）和完整的 `metadata_json`。后者由代理写入的字段包括 `target_url`、`status`、`success`、`duration_ms`、`trace_id`、`error_message`、`requested_model` / `upstream_model` 等。

::: details 自己查库时要注意两个键
新写入的行把响应预览放在 `metadata_json.response_body_br`（brotli 压缩后 base64），升级前的旧行是明文 `response_body`。只认 `response_body` 会把压缩过的行全部当成「没有响应体」。诊断脚本同理，两种都要认。
:::

## 第 3 步：分清三种价格来源

`price_source` 决定金额该怎么理解：

| 值 | 含义 | 界面 |
| --- | --- | --- |
| `upstream` | 上游响应里带了明确价格 | 正常显示 |
| `estimated` | 本地按 token 与价格表算的 | 金额后加「估」 |
| `NULL` | 完全没有价格 | 显示 `-` |

优先级很明确：**上游报了价就用上游的，绝不覆盖**。只有两个价格列都为空时才估算。Anthropic、OpenAI、Gemini 官方只返回 token 数不返回价格，所以走官方账号的请求基本都是「估」。

代理解析价格时也做别名兜底：`price_usd_micros` / `cost_usd_micros` / `cost_micros` 直接当微单位，`price_usd` / `cost_usd` 自动 ×1,000,000；只有 `price` / `cost` 的泛化对象会先识别货币（含 `usd`/`dollar`/`$` 归 USD，`cny`/`rmb`/`yuan`/`¥` 归 CNY）。

::: warning 未知模型不算免费
价格表里找不到的模型**不会被当成 0**——`price_source` 留 `NULL`，金额不计入总额，同时面板单独告诉你有多少请求因此没算钱。这样「缺价格数据」和「真的不花钱」能区分开。
:::

## 第 4 步：配一份自定义价格表

中转站的折扣价、还没进内置表的新模型，都可以在 `~/.ai-switch/model-prices.json` 覆盖：

```json
{
  "claude-opus-5": { "input_per_mtok": 4.0, "output_per_mtok": 20.0 },
  "claude-sonnet": { "input_per_mtok": 1.5, "output_per_mtok": 7.5 },
  "my-relay/gpt-4o": { "input_per_mtok": 0.8, "output_per_mtok": 2.4 }
}
```

单位是**每百万 token 的美元价**。键可以是完整模型 ID，也可以是模型族（`claude-sonnet` 会命中所有 Sonnet）。内置表按模型族匹配，缓存 token 按 Anthropic 公开规则计价：**缓存写入 = 输入价 × 1.25，缓存读取 = 输入价 × 0.1**。

匹配前会先归一化模型 ID：去掉厂商前缀（`anthropic/claude-opus-5-aws` → `claude-opus-5-aws`）、去掉 `[1m]` 后缀，然后按**最长模式优先**匹配，所以 `claude-haiku-4-5` 不会被更宽的 `claude` 抢走。

> ✅ **检查点**：改完再发一条请求，请求列表里原本显示 `-` 的行变成带「估」的金额。

::: tip 文件不存在是正常情况
不建这个文件不算错误。写坏了会**静默回退到内置表**，负数和非法数值被丢弃而不是污染总额。所以「改了没生效」先去检查 JSON 语法和模型名有没有写对。
:::

估算值毕竟是估算：缓存 token 上游通常只给一个合计数、不拆读写，估算时按较便宜的读取价计，结果偏保守。

## 第 5 步：一次月度对账怎么做

1. **选窗口**：统计切到「本月」。记住它只有起点没有终点，别拿它当分桶。
2. **过滤测试流量**：看「来源」列，把 `route_pool_model_test` 与 `route_pool` 的行单独记下来，它们是手工测试不是业务流量。
3. **按账号分组**：账号名列就是实际承载流量的凭据，对照每个供应商后台的账单。
4. **分开三类金额**：`upstream`（上游实价）、带「估」（本地估算）、`-`（无价格）。**只有第一类能和账单直接对**。
5. **核对汇率**：总费用卡片把 CNY 按固定 7.1 折成 USD，混用币种时它会偏离真实账单；逐行看原始币种金额更准。
6. **别跨平台相加**：统计查询按 `platform` 隔离，没有跨平台汇总视图，要自己逐平台导出/记录。
7. **别归档账号**：归档后该账号的历史事件因 `INNER JOIN` 从统计里立刻消失，取消归档才回来。对账完成前不要动归档。

::: warning 账号列表里的成功率是另一套口径
账号行上的请求数与成功率只算 `route_proxy` 与 `route_pool_model_test` 两种来源，且是**全历史累计**、不跟统计面板的时间选择变化。所以同一个账号在「当日」统计里和在账号列表里看到的数字不一样，不是 bug。
:::

## 第 6 步：本机会话用量怎么看

统计面板下半部分的「本机会话用量」读的是 CLI 自己的会话文件，**只读**，不会改动或删除：

| 客户端 | 路径 | 环境变量覆盖 |
| --- | --- | --- |
| Claude Code | `~/.claude/projects/**/*.jsonl` | `CLAUDE_CONFIG_DIR` |
| Codex CLI | `~/.codex/sessions/**/*.jsonl` | `CODEX_HOME` |

两套格式的计数规则完全不同：Claude Code 必须按 `message.id` 去重（续写与上下文压缩会把同一条消息写进多个文件，不去重实测虚高 93%）；Codex 的 `total_token_usage` 是**会话累计值**，只能取最后一个（逐个相加实测虚高 350 倍）。会话用量的费用**一定是估算值**，且缓存写入与读取分成两张卡。

::: danger 两套数字不要相加
路由统计看「经过代理的流量」，会话用量看「这台机器上所有 CLI 开销」。一次经过本应用代理的 Claude Code 请求**两边都会记一次**，它们是两个视角，不是可以相加的两部分。
:::

首次扫描可能要一百多秒（按文件 mtime+size 缓存，热扫描约 1 秒），刷新间隔 **60 秒**（路由统计是 5 秒）；文件数超过 5 万会截断，面板会明确提示「以下数字不完整」。

## 第 7 步：数据库变大了怎么办

`response_body` / `response_body_br` 是最占空间的东西且从不清理。成功率、耗时、token、价格都已提成独立列，**删掉响应预览不影响任何统计数字**。

设置页「用量历史的存储 → 清理缓存的响应内容」可选 7 / 30 / 90 天前或「全部」，分批独立事务、可中断可续跑，只重写 `metadata_json` 不删整行。

::: warning 清理 ≠ 文件变小
删除只是把字节变成 SQLite 空闲页供后续复用，真正把空间还给文件系统的是「整理数据库」（`VACUUM`）。所以清理之后要接着点整理才能看到体积下降。
:::

## 排错表

| 现象 | 原因 | 怎么修 |
| --- | --- | --- |
| 价格显示 `-` | 上游没报价且模型不在内置价格表 | 配 `~/.ai-switch/model-prices.json` |
| token 显示 `-` | 上游响应没带 usage | 这是刻意的，AI Switch 不用字符数反推 token；换会返回 usage 的上游 |
| 金额都带「估」 | 上游（官方 API）只返回 token 不返回价格 | 正常；用自定义价格表把估算调准 |
| 总费用与账单差得多 | CNY 按固定 7.1 折算 + 估算价混入 + 测试流量混入 | 逐行看原始币种金额，排除测试来源 |
| Token 总计比输入+输出大 | 混入了历史遗留的独立 `token` 事件 | 属既有口径，不是重复计数错误 |
| 请求数莫名偏高 | 频繁点 ✈ 模型连通性测试 | 看「来源」列，少点测试 |
| 归档后历史数字消失 | 统计 `INNER JOIN` 未归档账号 | 取消归档 |
| 会话用量首次打开一直转 | 冷扫描上千个 jsonl 文件 | 等一次，之后走缓存 |
| 清理了响应内容但文件没变小 | 空闲页未归还 | 点「整理数据库」（VACUUM） |
